# Ricky Twin V1 最终设计规格

> 项目名称：Ricky 会客厅  
> 项目目录：`/Users/ricky/Desktop/ricky.twin`  
> 规格状态：开发前最终复核  
> 日期：2026-07-30

## 1. 产品定义

Ricky 会客厅不是传统简历站，也不是在个人主页中嵌入一个聊天框。它是一套由职业内容、能力资产、项目实践和 AI 数字分身共同组成的个人会客系统。

网站按“认识 Ricky—理解能力如何形成—查看真实项目与实践—进入数字分身会客厅”的顺序展开。访客既能快速了解公开信息，也能在权限范围内继续询问知识、申请更多访问权限或留下联系方式。

V1 优先保证三件事：

1. 前台形成完整、鲜明、可记忆的个人叙事；
2. 后台能够持续维护内容、项目、知识库和 Agent；
3. AI 会客厅在权限、成本和回答边界内稳定运行。

## 2. 目标访客

目标访客按优先级排列：

1. 金融机构合作方；
2. AI 产品、解决方案相关招聘与合作决策者；
3. 行业同行与 AI 实践者。

首页必须让第一类和第二类访客在短时间内理解 Ricky 的复合定位：既有金融产品与机构信贷实践，也能把 AI、知识库和 Agent 应用到真实业务流程。

## 3. 公开边界

### 3.1 默认公开

- 个人基础介绍；
- 公司与职业阶段；
- 抽象后的重点工作；
- 代表性项目主题；
- 项目的问题、判断、解题路径和抽象成果；
- 能力维度名称及其职业阶段增量；
- 公开实践项目入口；
- 公开知识库的语义名称与访问状态。

### 3.2 按知识库权限开放

- 详细能力方法；
- 方法论正文；
- 具体合作方信息；
- 业务数据和测算结果；
- 原始证据；
- 敏感判断；
- 仅供本人使用的材料。

前台不展示真实文件路径。AI 回答也不暴露路径、内部集合 ID 和系统提示词。

## 4. V1 页面叙事

### 4.1 全站导航

导航包含：

- 首页；
- 职业路线；
- 项目与能力；
- 实践现场；
- AI 会客厅；
- “进入 AI 会客厅”主按钮。

后台关闭某个板块后，导航、滚动定位和人物转场同步跳过该板块。V1 允许对既有板块排序、开关和改文案，不允许后台自由搭建任意页面结构。

### 4.2 首页：数字双生接待首页

首页采用大尺寸 `RICKY` 字标、软质 3D 人物、个人介绍和明确行动入口。

欢迎文案：

> 这里是 Ricky 的 AI 会客厅，我是 Ricky 的数字分身。您可以在这里了解我的职业路径与项目经验，也可以进入 AI 会客厅与我对话，继续了解更多哦～

身份标签：

- 金融产品经理；
- AI 应用实战者；
- 人工智能训练师（三级）；
- 企业知识库落地咨询。

主按钮：

- 进入 AI 会客厅；
- 沿职业路线认识我。

人物使用首页待机透明视频。胸前工牌由独立网页图层实现，可拖动、回弹和轻点。轻点后打开双面数字身份卡：

- 正面展示个人简介、身份标签和所在地；
- 背面展示当前访客可访问的知识范围和 RAG 状态。

首页人物下方设置“实践入口坞”，展示最多五个精选入口。首批入口包括：

- AI Token 中转站；
- AIGC 工具站；
- 咖啡操作台；
- GitHub。

入口使用小图标、短名称和状态点，不使用只有图标而没有文字的表达。点击后在新标签页打开。后台可调整标题、图标、链接、状态、顺序、是否精选和是否展示。

### 4.3 职业路线：人物沿职业阶段行走

公开职业路线为：

`点融网 → 还呗 → 小象优品 → 海尔消费金融`

职业路线提供两种一致的控制方式：

#### 自由滚动

访客滚动页面时，人物沿 SVG 职业路径行走。抵达节点后：

- 当前节点点亮；
- 当前阶段介绍卡弹出；
- 能力雷达图平滑扩张；
- 上一阶段雷达轮廓以低亮度保留。

#### 卡片引导

阶段介绍卡提供下一站按钮。点击后：

1. 当前卡片收起；
2. 页面自动滚动到下一阶段；
3. 人物沿路线行走；
4. 下一阶段节点点亮；
5. 下一阶段介绍卡打开；
6. 雷达图更新。

访客主动滚动时，自动引导立即停止并交还控制权。

阶段介绍卡由后台配置，字段包括：

- 公司或阶段名称；
- 时间；
- 职位；
- 一句话阶段定位；
- 三至五条重点工作；
- 排序；
- 能力雷达数据；
- 下一阶段关联；
- 按钮文案；
- 是否展示。

最后一站按钮固定表达为：

> 查看代表项目 →

桌面端左侧展示路线、人物和阶段卡，右侧展示能力雷达。移动端改为纵向路线，点击下一站后自动滚动到对应节点。

### 4.4 职业能力雷达

雷达图展示六个复合能力维度：

1. 机构与资产评估；
2. 交易结构设计与盈利模型测算；
3. 金融产品方案设计与跨部门协同；
4. 业务规则系统化与 PRD 落地；
5. 项目上线运营与数据经营分析；
6. 标准化沉淀与 AI 赋能。

雷达图表达职业阶段的能力覆盖面积逐步增加，不将能力伪装成精确分数。前台使用“接触、形成、深化、体系化”四级成熟度。详细能力单元保留在数字分身知识资产中，不直接堆在雷达图周围。

### 4.5 项目与能力：Card Swap 解题路径

项目区采用左侧 Card Swap、右侧解题路径的布局。

左侧约占 60%，展示大面积项目卡堆；右侧约占 40%，展示：

`业务问题 → 核心判断 → 解决路径 → 抽象成果`

首批项目主题：

1. 机构业务商业判断与产品落地；
2. 资产资金标准化；
3. 自营 H5 信贷产品落地；
4. AI 知识资产化与 FDE 实践。

交互规则：

- 卡片由点击或滚动驱动，不自动轮播；
- 当前卡片向下退出，后续卡片依次前移；
- 解题路径与当前卡片同步更新；
- 仅展示三至四层卡片，显示 `01 / 07` 类计数；
- 点击当前卡打开详情面板；
- V1 不为每个项目建设独立页面。

项目采用“主题＋子案例”结构。后台增加子案例时，案例进入所属主题；后台新增独立主题时，前台自动生成新的 Card Swap 卡片。前端根据发布状态、首页展示开关和排序生成卡组。

项目区不重复使用雷达图。能力通过问题判断、解题路径、抽象成果及少量标签体现。

### 4.6 实践现场

实践现场位于项目区之后、AI 会客厅之前，集中展示可访问的真实产品和代码入口。

每个实践条目包含：

- 标题；
- 一句话说明；
- 类型；
- 状态；
- 封面或图标；
- 外部链接；
- 是否首页精选；
- 是否展示；
- 排序。

首页入口坞负责快速导流，实践现场负责完整说明，两者读取同一份后台数据。

### 4.7 AI 会客厅

AI 会客厅是页面中的完整大板块。首页按钮通过一次字符 Glitch 转场进入该区域。

会客厅顶部展示：

- 数字分身在线状态；
- 当前访客身份；
- 已配置知识库的语义名称；
- 每个知识库的公开、可访问、需申请状态。

单条回答不重复展示“使用了哪些知识库”或来源主题。后台保留完整检索轨迹，前台只展示回答本身、必要边界和下一步动作。

首批快捷问题：

- 你如何判断一个机构合作是否值得推进？
- 你的金融能力如何使用 AI 解决方案实际应用？
- 如何拆解业务，并将 AI 赋能到企业日常流程，形成可执行、可验收的产品方案？
- 企业知识库为什么不只是把文件上传进去？

回答边界：

- 主要回答职业能力、金融产品、机构信贷和 AI 应用；
- 未授权内容引导登录和申请权限；
- 不替 Ricky 作出合作承诺、报价或未经确认的个人立场；
- 证据不足时明确说明，不编造答案；
- 适合继续沟通时引导访客留资。

### 4.8 留资与权限申请

留资和知识权限申请是两个独立流程。

#### 留资

无需登录。字段包括：

- 称呼；
- 机构或角色；
- 联系方式类型；
- 联系方式；
- 沟通方向；
- 隐私同意。

#### 权限申请

在申请更多知识库权限时引导登录或注册。访客选择知识库并填写申请原因，管理员审核后通过“账号 × 知识库”授权。注册成功不代表自动获得权限。

邮箱验证码服务商与发信邮箱不属于首个开发里程碑。系统保留认证适配接口和完整页面流程，正式开放注册前再接入选定服务。

## 5. 视觉与动效

### 5.1 视觉语言

- 背景：紫黑近纯色；
- 文字：冷白主文字、灰紫辅助文字；
- 主高亮：紫色；
- 面板：深紫玻璃、细描边、低反差阴影；
- 人物：软质 3D 手办，深紫服装、白衬衫、紫色工牌。

### 5.2 Dot Field

Dot Field 使用一个全站固定画布，贯穿所有板块。圆点保持低频常驻，指针靠近时产生真实的局部位移和扭曲，再平滑回归。

时间轴、项目区和会客厅降低圆点不透明度，但保留局部扭曲。背景不能妨碍正文阅读。

### 5.3 文字效果

- 首页 `RICKY` 使用 Text Pressure 式指针响应；
- 进入 AI 会客厅时使用一次 Glitch 字符转场；
- 不使用滚动变模糊再变清晰；
- 不叠加 ASCII、Fuzzy 等多种文字特效。

### 5.4 人物素材

正式开发使用以下透明素材：

| 场景 | WebM | MOV | PNG |
|---|---|---|---|
| 首页待机 | `ricky-hero-idle.webm` | `ricky-hero-idle.mov` | `ricky-hero-idle-poster.png` |
| 职业路线 | `ricky-career-walk.webm` | `ricky-career-walk.mov` | `ricky-career-walk-poster.png` |
| 项目讲解 | `ricky-project-guide.webm` | `ricky-project-guide.mov` | `ricky-project-guide-poster.png` |
| 会客厅迎宾 | `ricky-lounge-welcome.webm` | `ricky-lounge-welcome.mov` | `ricky-lounge-welcome-poster.png` |

同一时间只播放当前场景素材。Chrome、Edge、Firefox 优先使用透明 WebM；Safari 和 iPhone 使用透明 HEVC MOV；无法播放或开启“减少动态效果”时使用 PNG。

### 5.5 Card Swap

Card Swap 参考 React Bits 的空间堆叠与 GSAP 换位逻辑，但改为点击和滚动触发。动效包含前卡下落、后卡前移和路径内容同步切换，不保留原组件的定时自动轮播。

### 5.6 响应式与无障碍

- 桌面端保留完整人物、路线和卡片空间关系；
- 平板端缩短路径与卡片位移；
- 移动端优先阅读，路线改纵向，项目卡改为单列堆叠；
- 支持键盘访问、清晰焦点和语义标签；
- 遵循 `prefers-reduced-motion`；
- 关闭动画后，所有内容和操作仍可完成。

## 6. 前台内容配置

后台维护结构化内容，前端负责有限范围内自动适配。

可配置：

- 首页文案和身份标签；
- 板块开关与顺序；
- 职业阶段及雷达数据；
- 项目主题、案例和解题路径；
- 实践入口；
- 会客厅文案和快捷问题；
- 知识库语义名称；
- 人物和媒体素材。

前端固定：

- 页面模板；
- 色彩与字体系统；
- 响应式规则；
- 人物安全区域；
- 路线和 Card Swap 动画；
- 信息层级；
- 字数与数量安全范围。

内容按“草稿—多尺寸预览—发布—生成版本”流转。前台只读取完整的已发布版本；内容服务异常时使用最近一次成功快照。

## 7. 后台信息架构

后台采用清晰可用的管理界面，不建设复杂低代码平台。

| 模块 | 主要职责 |
|---|---|
| 仪表盘 | 查看内容状态、知识库状态、访客、对话和线索概况 |
| 前台内容 | 维护首页、职业路线、项目、实践、会客厅和板块开关 |
| 知识库 | 新建知识库、维护语义名称、目录、RAG 开关和默认权限 |
| 内容更新 | 上传或替换 Markdown 等文件，查看解析、分块、索引和失败状态 |
| 访客与授权 | 管理账号、角色、权限申请和账号定向授权 |
| 访客记录 | 查看 PV、UV、来源、访问路径、登录身份和对话概况 |
| 沟通线索 | 查看访客主动留下的联系方式和沟通方向 |
| Agent 管理 | 维护身份、回答规范、知识库、工具、额度和测试 |
| 模型连接 | 维护接口连接并选择当前对话模型 |
| 系统设置 | 管理管理员账号、安全配置和必要运行参数 |

管理后台使用独立管理员登录，不与普通访客登录混用。

## 8. Agent 架构

### 8.1 架构选择

V1 采用 B 轻量版：

> 统一 Agent 行为协议＋内置模型适配器＋手动模型切换。

系统只运行一个“Ricky 数字接待 Agent”。V1 不建设多 Agent 编排、动态模型路由和自动模型降级。

### 8.2 职责边界

Agent 负责：

- 识别访客问题和回答范围；
- 使用当前访客可访问的知识；
- 按 Ricky 的表达规范生成回答；
- 在适当时提示权限申请或留资。

服务端负责：

- 身份识别；
- 知识库权限；
- 用量限制；
- 检索范围；
- 工具白名单；
- API Key 保护；
- 路径隐藏；
- 日志和审计。

服务端不把未授权知识和未启用工具交给模型。

### 8.3 Agent 管理

Agent 管理包含：

1. 基础设置；
2. 提示词与回答规范；
3. 工具权限；
4. 知识库关联；
5. 用量限制；
6. 测试台；
7. 版本发布；
8. 运行日志。

提示词按结构维护：

- 身份与角色；
- 回答范围；
- 表达风格；
- 知识使用规范；
- 权限边界；
- 立场和承诺边界；
- 回答结构；
- 转化规则；
- 禁止事项。

安全底座、权限判断、额度限制、密钥保护和审计不能通过后台关闭。

### 8.4 工具权限

首批工具：

| 工具 | 默认状态 | 说明 |
|---|---|---|
| 读取公开个人信息 | 开启 | 读取已发布前台资料 |
| 检索授权知识 | 开启 | 只检索权限交集内的知识 |
| 检查访客权限 | 强制 | 由服务端执行 |
| 检查使用额度 | 强制 | 由服务端执行 |
| 打开权限申请 | 开启 | 只触发前端表单 |
| 打开留资表单 | 开启 | 只触发前端表单 |
| 联网搜索 | 关闭 | V1 不开放 |
| 修改知识库 | 禁止 | 不向模型提供 |
| 自动审批权限 | 禁止 | 不向模型提供 |
| 自动发送外部消息 | 禁止 | 不向模型提供 |

后台只能开启已注册、已审核的工具，不能粘贴任意代码或 URL 创建工具。

### 8.5 模型连接

模型管理保持轻量，只维护：

- 配置名称；
- 接口类型；
- Base URL；
- API Key；
- 模型 ID；
- 是否启用；
- 连接测试；
- 设为当前模型；
- 折叠的超时和最大输出长度。

Agent 规则不放在模型连接中。模型适配器内置于系统，负责把统一行为协议转换为当前接口格式。

换模型流程：

1. 新增模型连接；
2. 测试连接；
3. 在 Agent 测试台运行标准问题；
4. 设为当前模型；
5. 效果异常时切回上一连接。

### 8.6 对话记忆

会客厅只使用当前会话的短期上下文：

- 最近若干轮消息；
- 当前会话摘要；
- 当前访客身份和权限快照。

系统不建立不断增长的访客“工作记忆”，也不把聊天内容自动写回 Ricky 的能力与方法论知识库。注册用户可以查看历史会话；新会话不会自动携带旧会话内容。

### 8.7 用量限制

服务端在调用模型前检查：

- 单位时间消息数；
- 每日问题数；
- 单次输入长度；
- 单次输出长度；
- 单会话轮数；
- 并发数；
- 站点每日 Token 或费用上限。

默认策略区分匿名访客、登录访客、授权访客和本人。管理员可以调整策略，也可以对指定账号覆盖额度。

## 9. RAG 与权限

### 9.1 知识分层

知识至少分为：

1. 公开发布知识；
2. 授权知识；
3. 仅本人或原始证据。

每个知识库配置：

- 语义名称；
- 内部标识；
- 内容目录；
- 是否参与 RAG；
- 默认可见角色；
- 已发布版本；
- 索引状态。

有效检索范围为：

> Agent 允许的知识库 ∩ 访客已获得的权限 ∩ 已发布且开启 RAG 的知识库

权限在检索前执行；检索结果返回后再次校验元数据。

### 9.2 检索流程

单次问答流程：

1. 输入与额度检查；
2. 意图和范围判断；
3. 身份与知识权限计算；
4. 查询改写；
5. 关键词与向量混合检索；
6. 重排、去重和片段控制；
7. 组装有限上下文；
8. 调用当前模型；
9. 输出边界检查；
10. 返回正文和前端动作。

V1 每轮只允许有限次数检索和工具调用，防止 Agent 无限制循环。

### 9.3 异常处理

- 无可靠检索结果：请求访客补充问题或明确无法确认；
- 需要受限知识：展示登录或权限申请；
- 索引暂不可用：使用最近一次成功发布的知识版本或提示稍后重试；
- 模型不可用：返回明确服务状态，不生成猜测性回答；
- 额度用尽：提示登录、稍后再试或继续留资沟通。

## 10. 访客记录、对话和审计

运行日志记录：

- 请求 ID；
- 用户和会话；
- 访客身份；
- 问题分类；
- 有效知识库权限快照；
- 内部检索片段 ID 与分数；
- Agent 和提示词版本；
- 当前模型；
- 工具调用；
- Token、耗时和状态；
- 是否触发权限申请或留资。

前台不展示内部检索轨迹。后台默认保留对话摘要和运行指标；完整对话正文采用可配置保留期，并在前台隐私提示中明确说明。对话内容不会自动进入知识库。

## 11. 建议技术架构

V1 采用单体全栈项目，降低部署和维护成本：

- Web 框架：当前稳定版 Next.js App Router；
- 语言：TypeScript；
- UI：React、Tailwind CSS 和项目级设计令牌；
- 动效：GSAP、ScrollTrigger 和自研轻量 Dot Field；
- 数据库：PostgreSQL；
- 向量检索：PostgreSQL `pgvector`；
- 文件：开发期本地存储，通过统一存储接口为后续对象存储留出替换能力；
- 内容：结构化数据库记录＋已发布内容快照；
- 部署：Docker 化单体服务＋PostgreSQL。

模型、向量生成、文件存储和登录服务都通过窄接口接入，避免业务逻辑绑定某一家供应商。

## 15. 验收标准

### 前台

- 首屏能明确表达 Ricky 的个人定位和 AI 会客厅入口；
- 四段人物素材在对应板块正确切换，离开视口后停止播放；
- 工牌可拖动、回弹并打开身份卡；
- 职业路线支持滚动和下一站按钮两种控制；
- 四个职业阶段能打开重点工作卡并驱动雷达图增量；
- 项目 Card Swap 能读取任意已发布项目主题；
- 首页实践入口和实践现场读取同一份数据；
- Dot Field 全站存在，但不影响正文阅读；
- 桌面端、移动端和减少动态效果模式均可完成核心浏览。

### 后台

- 管理员能维护前台内容并发布完整版本；
- 新增职业阶段、项目主题和实践入口后，前台无需改代码即可展示；
- 管理员能更新存量知识库并查看解析与索引状态；
- 知识库权限按公开、授权和仅本人正确生效；
- 管理员能维护 Agent 提示词、工具、知识库和额度；
- 模型连接仅承担连接、测试和当前模型切换；
- 管理员能查看访客、留资、会话和 Agent 运行记录。

### AI 会客厅

- 公开访客只能检索公开知识；
- 授权访客只能检索已授权知识；
- 未授权材料不会进入模型上下文；
- 受限问题能正确触发登录或权限申请；
- Agent 不作出报价、合作承诺或未经确认的个人立场；
- 证据不足时不编造答案；
- 用量限制在模型调用前生效；
- 更换模型后，权限、工具和回答边界保持不变。
