# Ricky Twin 运营与运行中心 V1 设计

## 目标

把现有“访客与运行”升级为轻量、可排障、可追踪转化的“运营与运行中心”，同时保持内容、知识库、Agent 与模型配置的现有存储和升级保护边界不变。

## 设计原则

1. 不复制 API 网关的重型运维系统，只采集 Ricky Twin 真正需要的指标。
2. 监测写入不得阻塞前台浏览和 AI 流式首字。
3. 问答正文与运行指标分层存储；列表只读摘要，详情按需解密。
4. 默认保存完整访客问答 30 天，管理员可关闭或配置 1～90 天。
5. 不记录 API Key、Cookie、系统提示词、RAG 原文、真实文件路径和模型内部推理。
6. 原运行 JSON 保留用于限额和线索，新增独立 SQLite 监测库，后续可通过接口迁移 PostgreSQL。

## 后台结构

后台侧栏将“访客与运行”改名为“运营与运行”，包含五个页签：

1. **运营总览**：PV、UV、AI 调用、成功率、Token、留资、趋势和异常摘要。
2. **访客与转化**：板块曝光、导航、项目详情、会客厅、留资等关键行为和漏斗。
3. **AI 与 RAG**：模型、TTFT、完整耗时、输入/输出 Token、召回、重试、错误和问答详情。
4. **请求与审计**：关键 API 请求日志及后台写操作记录。
5. **系统性能**：CPU、内存、磁盘、事件循环、数据库体积、悬挂任务和存储健康。

## 数据边界

新增持久化文件 `data/observability/monitoring.sqlite`，包含：

- `settings`：问答保存开关与保留天数。
- `ai_runs`：AI 运行指标、加密问答和关联请求编号。
- `behavior_events`：白名单行为事件。
- `request_logs`：脱敏后的关键 API 日志和后台操作。
- `system_samples`：低频系统性能样本。

问答正文使用现有 AES-256-GCM 密钥体系加密。后台列表不返回正文；管理员点击详情时单独读取、解密并留下审计记录。

## 保留与清理

- 默认保留 30 天，允许 1～90 天。
- 保存设置后立即影响新记录；到期记录按小批次自动清理。
- 管理员可执行“立即清理过期日志”，操作需要二次确认。
- 统计卡片按当前保留范围计算；后续需要跨年度趋势时再增加不可识别的日汇总表。

## 采集事件

V1 只采集业务有意义的事件：`page_view`、`section_view`、`navigation_click`、`project_detail_open`、`lounge_enter`、`chat_submit`、`chat_complete`、`chat_error`、`lead_form_open`、`lead_submit`、`access_request_click`、`external_link_click`。

不采集键盘输入、鼠标轨迹、完整 IP 或无意义 hover。

## 健康与性能

- `/api/health` 作为轻量存活检查，不再每 20 秒读取全部工作区。
- `/api/health/ready` 作为深度就绪检查，供后台按需调用。
- 系统样本最多每 30 秒记录一次；健康检查和关键请求均可触发采样。
- 超过 5 分钟仍为 pending 的 AI 运行标记为悬挂并在后台提醒。

## 验收标准

1. 每次关键请求均有请求编号，可关联 AI 运行和问答详情。
2. 流式失败也能记录部分回答、错误类型和最终状态。
3. 后台能配置完整问答保存开关及 1～90 天保留期。
4. 后台列表不会加载或返回完整问答；详情按需解密。
5. 日志不包含密钥、系统提示词、RAG 原文和真实路径。
6. 原有 199 项测试继续通过，并新增监测存储、AI 运行、行为事件和后台交互测试。
